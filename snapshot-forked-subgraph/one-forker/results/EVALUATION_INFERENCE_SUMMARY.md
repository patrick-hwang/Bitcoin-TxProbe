# Past Block Propagation Backward Inference & Topology Comparison Summary

This document summarizes the results of the updated blockchain fork propagation experiment and backward network propagation inference engine executed on `fork_subgraph_height_102.json` across 1,000 nodes in the Bitcoin RegTest network.

---

## 1. Stop Condition & Non-Redundant Snapshotting

### Optimization
Previously, the experiment continued logging snapshots well past 100% convergence (taking 26 sliced snapshots through 250 ms, of which snapshots 13–25 were identical static states with 1,000 nodes on B3).

In this update:
1. **Dynamic Stop Condition**: `run_experiment.py` (both simulation and live modes) tracks when 100% of target nodes have received the reorganization block B3.
2. **Immediate Termination**: `SubgraphTracker.generate_sliced_snapshots` accepts `stop_on_convergence_hash` and terminates immediately after capturing the first snapshot with 100% network adoption.
3. **Execution Results**: Exactly 13 snapshots (0–12, covering 0.0 ms to 120.0 ms with $\Delta = 10\text{ ms}$) were produced. Snapshot 12 marks the exact moment of 100% convergence (1,000 nodes adopted B3), after which snapshot generation terminated with zero trailing redundant snapshots.

## 2. RegTest Topology Verification

### Verification Methodology
We investigated whether `groundtruth_topology.json` accurately reflects the active peering of the 1,000 running RegTest nodes:
1. **Process Inspection**: Exactly 1,002 `bitcoind` processes are active on the host:
   - Probes 0 and 1: Custom bitcoind (`/mnt/ssd/hdhphat-mindfullab/Bitcoin-TxProbe/build/bin/bitcoind`) with `-txprobelogfile`.
   - Target Nodes 2..1001: 1,000 standard bitcoind instances (`/mnt/ssd/hdhphat-mindfullab/bitcoin-31.1/bin/bitcoind`).
2. **Peering Status**:
   - `groundtruth_topology.json` defines the canonical 4,005 undirected edges (mean degree ~8.01) generated by `manage_regtest.py build-topology`.
   - In the active daemons, node configurations specify `discover=0` (disabling automatic P2P peer discovery). When the daemons were restarted without re-running the connection dispatch, the in-memory peer table (`getpeerinfo` and `getaddednodeinfo`) showed 0 active peers.
   - P2P peering is established deterministically via `connect_network_topology` (invoked in Step 0 of `run_experiment.py` or via `manage_regtest.py build-topology`), which iterates over `groundtruth_topology.json` and issues RPC `addnode` commands to interconnect all target nodes and connect both probes to all 1,000 nodes.
   - **Conclusion**: `groundtruth_topology.json` is the authoritative topology design file for the 1,000 RegTest nodes; active P2P connections are established dynamically from this file via `addnode`.

### Key Observations
1. **Near-Perfect Congruence**: Because the TxProbe inferred topology captured 3,958 of the 4,005 ground truth edges with only 4 false positive edges (99.899% edge precision), the backward propagation inference results between Ground Truth and Inferred topology are virtually indistinguishable:
   - For B1 and B2: Mean accuracy, precision, recall, and F1 are identical to 4 decimal places.
   - For B3: Accuracy differs by only $0.01\%$ (96.55% vs 96.54%), and precision differs by only $0.01\%$ (87.26% vs 87.25%).
2. **Robustness of Backward Constraint**: The backward inference rule $U(t - \Delta) = U_t \cup \mathcal{N}(U_t)$ proves to be highly resilient against minor missing edges in the inferred graph, maintaining over 96% accuracy across dynamic propagation wavefronts.
